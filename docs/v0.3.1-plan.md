## 1 Goal and scope

**The release is done when** a reader who opens Posture sees, without scrolling, how many checks ran, which
three need attention and why observation was incomplete; and a reader who finishes a Source Scan sees, before
the first finding, the severity distribution, whether the findings are one rule or many, and how much of the
source was actually analysed.

**In scope**

- Posture: summary band (unit strip + attention-ordered counts + coverage sentence + tools line), attention-first
  body with domain grouping and progressive disclosure, keyboard cursor, finder support.
- Overview, Plugin detail, Rules and Analysis: the completeness guard the candidate path gains, applied to the
  installed path (T12), and the disclosure/parity items of `08 §2.4` E3–E6 (T13).
- Source Scan: result summary band (severity bar, by-rule bars, capability strip, coverage bar), one
  reconciliation line replacing the five omission notices, keyboard cursor, finder support.
- Three new presentational components, two new pure JS modules, one node test.
- Tab chips carry counts; the bar tooltip gains a posture line.
- Optional rendering of two new CLI fields, feature-detected, absent-safe.

**Not in scope** — §8.

### T1 Tier palette extraction

**Goal.** One owner for semantic tier colours, so a bar, a strip and a row cannot drift apart.

**Change.** Move the `markColor` ladder and the `darkSurface` luminance test out of
`components/SemanticMark.qml` into a new pure module `model/Tiers.js`:

```js
.pragma library
function isDark(background) { … }          // 0.2126/0.7152/0.0722 luminance < 0.5
function color(level, dark) { … }          // healthy medium high critical incomplete low info → hex
function normalize(level) { … }            // the existing alias folding, moved verbatim
```

`SemanticMark.qml` keeps its public API unchanged and becomes the module's first consumer. `normalize()` gains
`not_applicable → notApplicable` and keeps `incomplete` distinct from `high` (they currently share the `alert`
glyph — T9 separates the glyph, T1 separates nothing else).

**Acceptance.** No visual diff on Overview, Analysis, Rules at four base sizes; `grep -n 'markColor' components/`
returns only `SemanticMark.qml`; `02 §2.3` amended in the same commit (decision D1).

### T2 Chart components

**Goal.** Three presentational primitives that satisfy CH1–CH10 and can be reviewed once instead of per view.

**Change.**

`components/UnitStrip.qml` — fixed-order unit chart.
- `cells: [{ key, glyph, level, tooltip }]`, `cellW: Style.space(11)` (the `CapabilityStrip` cell), `cursorIndex`,
  `focused`, `signal activated(int index)`.
- One fixed-width `Item` per cell so a wide Nerd glyph cannot overlap its neighbour — the `CapabilityStrip`
  technique, reused.
- Wraps to a second row via `Flow` when `cells.length * cellW > width`; never scrolls horizontally.
- A cell with `level: "absent"` renders `–`; a cell with `level: "none"` renders `·` (CH7).
- `PanelToolTip` on the hovered/cursored cell only.

`components/MeterBar.qml` — segmented length bar.
- `segments: [{ key, count, level, label }]`, `total`, `available` (default `true`), `trackHeight: Style.space(6)`.
- Segment width `Math.max(Style.space(2), count / total * width)` with the residual absorbed by the largest
  segment so the row always fills exactly (CH6).
- `BorderSurface` track at `Style.cornerRadius`; segment fill from `Tiers.color()`; **no** legend of its own —
  the caller prints the counts line, so a bar can never appear without its numbers (CH1).
- **Availability and zero are different states, and neither implies the other** (CH7):

  | State | Bar | Caller prints |
  |---|---|---|
  | `available: false` — the collection could not be read | no track at all | the word `unavailable` |
  | `available: true`, `total === 0` — a scan ran and measured nothing | empty track | the zero counts, e.g. `0 critical · 0 high · 0 medium · 0 low · 0 info` |
  | `available: true`, `total > 0` | segments | the counts |

  A measured zero is data and keeps its zeros; conflating it with `unavailable` would contradict CH7 and T5's
  empty-result acceptance, and would print "unavailable" over a scan that completed successfully.

`components/RankedBars.qml` — sorted count list.
- `rows: [{ label, count, level }]`, `maxRows: 5`, `total`.
- Sorts by count desc then label asc; bar width relative to the largest count, not to `total`; prints the count
  right-aligned; renders `+N more` when truncated.

All three: no `Style.font.pixelSize` literals, no bare pixel values, no motion beyond the kit's existing colour
behaviours, no `Color.accent` except through the kit.

**Acceptance.** `qmllint -I /usr/share/omarchy/shell -I /usr/lib/qt6/qml components/*.qml`; each component
instantiated in a scratch harness at base 9/12/16/20 and in `white`, `catppuccin-latte`, `retro-82`, `oxocarbon`;
a 1-of-33 segment is visibly non-zero; a zero segment is absent from the bar and present in the caller's counts.

### T3 Posture view-model

**Goal.** All ordering, grouping, counting and wording of the posture report happens in one testable pure module,
not in QML bindings. Fixes A1, A2, A3, A4 at the data layer.

**Change.** New `model/Posture.js`, mirroring `model/ViewModel.js`:

```js
build(report) -> {
  available, notYetRun, catalogVersion, generatedAt, ageSeconds, ageText, stale,
  host: [ {label, value} … ],
  strip:      [ { key, glyph, level, tooltip, checkIndex } … ],   // catalog order, CH8
  stateCounts:[ { key, label, count, level } … ],                 // attention order, CH8
  coverageSentence: "Observation completed for 14 of 18 checks. 2 incomplete, 2 not applicable.",
  tools: { observed, total, missing: [names], impactedChecks: N, sentence },
  attention: [ check … ],                                          // error regression incomplete attention
  groups:    [ { domain, label, count, checks: [ check … ] } … ],  // remaining, id-prefix grouped
  limitations: [ … ]
}
```

Per-check normalisation carries `id · domain · title · state · level · glyphKey · stateWord · evidence[] ·
evidenceSummary · limitations[] · nextStep · toolName · toolAvailable · previousState? · gapOpenSince?`.

Rules the module owns:
- **Catalog order** = `checks` sorted by `id` under a given `check_catalog_version`; a `catalog_index` field is
  preferred when the CLI supplies it (C3).
- **Attention order** = `error → regression → incomplete → attention → informational → pass → not_applicable`.
- **Domain** = the id prefix before the first `.`, upper-cased (D6).
- **Tool linkage** = a check is attributed to a missing tool when any `dependencies[]` entry names a `tools[]`
  entry with `available: false`. `impactedChecks` counts those.
- **`coverageSentence` is a sentence, never a count strip** — the deliberate fix for A3.
- **Never infer.** A missing field yields `null` and the view renders nothing, never a default.

`scripts/posture-test.js` follows the `scripts/candidate-test.js` pattern (`vm.runInContext` over the stripped
`.pragma library` source) and asserts, at minimum: the 18-check fixture produces the state counts of `08 §1`;
`not_yet_run` produces `notYetRun: true` with empty strip, groups and attention; a check whose tool is
unavailable is attributed; attention order is exact; catalog order is stable across two reports with the same
catalog version; an unknown state maps to `unsupported` and is counted, never dropped; a report with 0 checks and
a report with 40 checks both build.

**Acceptance.** `node scripts/posture-test.js` green; the module has no QML import and no `Style`/`Color`
reference; the captured real report round-trips.

**Change.**

`model/Candidate.js` gains derivations only — no new normalisation, no new boundary:
- `summary.severityRows` — the five tiers in attention order with `count`, `level`, `label`, drawn from

- `summary.ruleRows` — `ruleCounts` as `{label, count}` sorted desc.

### T7 Cursor sections and finder

**Goal.** `08 §5.6`. Fixes A6, B6 and restores P12 on both tabs. **Touches `Panel.qml` — requires go-ahead.**

**Change.**
- `sectionCount()` returns the number of **selectable targets**, not the number of rows on screen. For a
  horizontal section that is the number of cells or buttons: `posture-strip` returns `checks.length` (18 on this
  host, not 1) and `scan-summary` returns the number of enabled copy actions. `posture-attention`,
  `posture-groups`, `posture-checks` and `scan-findings` return their item counts. The stub
  `if (section === "posture") return 1` and its source-scan twin are removed.

  This is the whole point of the task: `moveCursorH()` (`Panel.qml:1040–1042`) clamps
  `selectedIndex` to `sectionCount() - 1`, so a horizontal section declaring `1` pins the cursor at index 0 and
  every cell and button after the first is unreachable — the same defect the task exists to fix, one layer down.
  A section whose count is a row count while its cursor indexes cells is the other way to get this wrong; keep
  the two identical.
- `visibleSections` for `activeTabKey === "posture"` / `"source-scan"` lists the sections that currently have
  rows, in visual order.
- `sectionIsHorizontal` keeps `posture-strip` and `scan-summary`; the new list sections are vertical.
- Rows adopt `CursorSurface` + `onHasCursorChanged: panel.ensureCursorVisible(this)` + the `PointerMoveGate`
  hover idiom already used by `OverviewView`.
- Enter: on a strip cell, move the cursor to that check and expand it; on a group, toggle; on a check, toggle; on
  a finding, toggle its evidence steps.
- `/` finder: two new result kinds — posture checks (match id, title, state word, evidence) and scan findings
  (match rule id, title, path). Selecting a result jumps to the tab, expands the item and places the cursor.

**No new keys.** `r`, `Esc`, `Enter`, `j/k/h/l`, `/` keep their meanings.

**Acceptance.** From a closed panel: `4`, `j` × 5, `Enter` expands the fifth posture row and the panel scrolls
it into view; `Esc` collapses then leaves; the same for `5` and the findings list; a live `journalctl --user`
interval over the whole walk is warning-free.

Specifically for the clamp: on the strip, `l` × 17 reaches **cell 18** and a further `l` does not wrap or
advance; `h` × 17 returns to cell 0; the tooltip and the linked check follow the cursor at every step. On
`scan-summary`, `l` reaches the last enabled copy action. Assert `sectionCount("posture-strip") === 18` against
the captured report rather than trusting the walk.

### T12 Completeness guard on the installed path

**Goal.** Close `08 §2.4` E1 and E2. The candidate strip stops drawing omission as absence in T5; this stops the
installed strip, the Matrix and the Rules green check from doing the same thing. **Touches `Panel.qml`.**

**Standing today (verified, and the reason this is a guard and not a bugfix).** `plugins analyze` uses the `full`
profile: `selection_strategy: canonical-full-v1`, `serialized_byte_limit: null`, every
`report_profile.omissions.*.omitted` is `0`, `sizing_recovery.applied` is `false`, and `model/ViewModel.js`
applies no display cap of its own. Installed counts are complete today. They stop being complete the moment the
CLI sets a limit on that profile or introduces another, and nothing in the panel would notice.

**Change.**

0. **Get the metadata to the model.** The verdict needs `report_profile`, and `buildVm()` never sees it. It is
   already cached per plugin — `cacheAnalysis()` stores `reportProfile` at `Panel.qml:3696` — but
   `resolvedAnalysisFor()` (`:3759`) returns `cached.report` alone, and `root.analysisReportProfile` is a single
   property describing only the *currently open* plugin. So:
   - Add `resolvedAnalysisEntryFor(plugin)` returning `{ report, reportProfile }` or `null`, applying the
     **identical** validity gate `resolvedAnalysisFor` already applies (digest · cliVersion · policyKey).
     `resolvedAnalysisFor` becomes a one-line wrapper so existing callers are untouched.
   - The pair is resolved **atomically**: a plugin whose analysis validates but whose profile is absent or
     invalid is `analysisExact: false`, never exact. The two must not be resolved by separate gates or a stale
     profile could be paired with a fresh analysis.
   - `buildVm()` (`:3775`) builds `profileById` in the same loop that builds `analysisById` and passes it to
     `ViewModel.build()`.
1. `model/ViewModel.js` derives one verdict per plugin, carried beside the existing `analyzed` flag:

   ```js
   analyzed:        true,   // we ran an analysis
   analysisExact:   true,   // …and every collection it drew from was emitted whole
   ```

   `analysisExact` is true **only** when, for each of the four consumed collections
   (`capabilities · findings · invocation_edges · coverage_gaps`), `report_profile.omissions[c]` is an object
   whose `total`, `emitted` and `omitted` are all finite non-negative numbers, `emitted + omitted === total`
   (the CH5 reconciliation, applied to the input rather than the output), and `omitted === 0`; and
   `sizing_recovery.applied !== true`.

   Everything else is false, including: no `report_profile`, an omissions block that is `{}`, a block missing
   any one of the four collections, an entry missing its `omitted` counter, and an entry whose counters
   contradict. **Absence of a counter is not evidence of zero** — that is the same GR3 reading that makes
   `unavailable ≠ clean`, applied to metadata.
2. `_capCounts()`, `_ruleOccurrences()` and `_pluginByClass()` are unchanged in arithmetic; their callers now
   carry `analysisExact` alongside the numbers.
3. `CapabilityStrip` gains a `complete` property, **default `false`**. When false, unobserved catalog positions
   render `–` instead of `·` and the row's tooltip gains `counts are at least this`. The default is false so a
   call site that forgets to bind it degrades to "we cannot claim completeness" rather than to a silent `·`;
   every existing call site is updated in this task, so the default is a backstop, not a behaviour. D4 is
   amended to permit this: it is a correctness property, not the `UnitStrip` merge.
4. **Wire the flag end to end**, so the strip is never left on its default in a real path:
   `Panel.resolvedAnalysisEntryFor` → `buildVm().profileById` → `ViewModel` plugin/backup rows
   (`analysisExact`) → `OverviewView` `PluginRow` delegate (`complete: modelData.analysisExact`) →
   `PluginRow.complete` → `CapabilityStrip.complete`; and the same flag to `PluginDetailView`'s strip and to
   `Panel.flowMatrixModel()`, which reads it off the vm row it already iterates. Backup rows keep
   `analyzed: false` and are unaffected.
4. `Panel.flowMatrixModel()` (`:2177–2178`) gains the third case: `!analyzed → "–"`, `analyzed && !analysisExact
   && n === 0 → "–"`, otherwise digit or `·`. The Matrix legend gains the distinction.
5. `RuleRow`'s green check requires `noLocalHits && analysisComplete && analysisExactForAll`. Where completeness
   is not established the row keeps its `0` in `dim` and **drops the mark** — no green, no red, no new state
   word. `buildBaseline().observedText()` takes the same guard: "not observed in N analyzed plugins" becomes
   "not observed in N analyzed plugins (counts may be incomplete)" only when the guard trips.

**Acceptance.**

*The no-change case, live.* Against a real `plugins analyze` report on this host, nothing changes on screen —
every strip, cell and green check renders exactly as today, because `analysisExact` resolves true. Verify in the
running shell, not only in the model: a plugin whose strip shows `·` before the change must still show `·`
after. If real reports start reading as incomplete, the metadata path of step 0 is wrong.

*The degradation cases, in `scripts/` unit tests over `ViewModel.build()`.* Each must yield
`analysisExact: false`, `–` at unobserved strip positions, `–` at matrix zero-cells, and **no** Rules green
check while the `0` count remains:

| Fixture | Why it must fail closed |
|---|---|
| `omissions.capabilities.omitted = 3` | the plain omission case |
| no `report_profile` at all | older or unknown report shape |
| `report_profile.omissions = {}` | present but says nothing |
| `omissions` missing `invocation_edges` | one consumed collection unaccounted for |
| `omissions.findings = { total: 10, emitted: 10 }` | `omitted` counter absent — not zero |
| `omissions.findings = { total: 10, emitted: 4, omitted: 2 }` | counters contradict |
| `sizing_recovery.applied = true`, all `omitted: 0` | the report was resized even though the counters look clean |
| analysis validates, cached `reportProfile` missing or stale | the atomic-pair rule of step 0 |

*Wiring.* Assert the flag is actually bound at each hop rather than trusting the default: a plugin with
`analysisExact: false` must reach `CapabilityStrip.complete === false` on an Overview row. `qmllint` clean and a
warning-free live load.

| Field | Type | Source | Semantics |
|---|---|---|---|
| `checks[].previous_state` | string \| null | **new persisted field — see the warning below** | The state this check held in the immediately preceding completed report. `null` on the first observation of a check — **not** the current state, and never omitted-as-equal. |
| `checks[].gap_open_since` | RFC-3339 string \| null | `posture-state.json → coverage_episodes[id].started_at` | When this check's current `incomplete`/`error` episode began. `null` when the check is not in a gap. |

### The `previous_state` trap

**Do not export `posture-state.json → previous_states`.** Despite the name it holds the states of the report
that produced it, not the preceding one: `update_state()`
(`crates/omasafe-posture/src/lib.rs:579`) does

```rust
let prior = state.previous_states.insert(check.id.clone(), check.state);
```

— the displaced prior value is bound to `prior`, used only to suppress duplicate notifications, and the map is
overwritten with the current state before the file is written. Exporting it would make `previous_state == state`
for every check, so T10 would render **zero** change marks on every run, and an absent mark reads as "nothing
changed" — a false quiet, which is the failure mode GR3 exists to prevent.

The value the panel needs already exists in that loop. The CLI change is to capture `prior` per check before the
insert and persist it (a sibling `prior_states` map, or the prior state written onto the report at generation
time), then export it. The panel-side guard is in T10's acceptance: a fixture where the exported
`previous_state` equals `state` for every check must render no delta marks, and that case must be produced
deliberately, not accepted as the normal result.

**Also worth fixing in the CLI while there:** `coverage_episodes[].started_at` currently serialises as a bare
unix-seconds **string** (`"1788872597"`) while `last_seen_at` in the same object is RFC-3339. The exported field
must be RFC-3339.

The panel does not read `~/.local/state/omasafe/` and this plan does not change that.
